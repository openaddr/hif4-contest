背景信息
高精度4Bit数值转换算法背景
随着ChatGPT、GPT4等大模型的发布与应用，生成式语言大模型（LLM: Large Language Model），已成为业界聚焦的技术热点。然而大模型推理面临高昂的部署成本，容易限制其应用推广。
量化是当前业界实现大模型推理加速的关键技术。短序列场景下（如2K以下），LLM推理表现为访存密集型，权重搬运开销是性能热点，通过对Linear层进行权重量化或权重激活量化，可有效提升推理性能；长序列场景下LLM的KV cache内存开销与整网计算量急剧上升，此时需要对Linear层、KV cache进行量化推理加速，以缓解所面临的计算与内存问题。
近年来，低精度计算成为提升训练效率和降低显存占用的关键路径。从 FP16 → FP8 → FP4 的演进趋势明显，4bit 已成为下一代大模型训练和推理的核心精度选择。各家算力产商对于4bit数值的定义存在差异，为了提升昇腾未来对于4bit推理生态的兼容性，更好的支持4bit模型的推理，需要完成其他4bit格式数据往昇腾HiF4进行转换，满足客户在使用昇腾或者昇腾、GPU混部时的4bit推理需求。

高精度4Bit数值转换算法挑战
Scale 层级断裂：不同4bit数据格式的量化层级不一样，其他4bit量化scale无法直接映射到 HiF4 的 E6M2+E1_8+E1_16 三级层级，需完全重构统计域与缩放逻辑
值集空间错位： 不同4bit的量化后数值的离散值集分布不同（如 4→6 间隔 vs 0.25 步长），反量化-再重量化引入二次截断误差。
Outlier 敏感度跃升： block size 16→64 使单个异常值稀释整组精度，需重新设计峰值隔离与层级补偿机制。

目标：
分别针对 Linear 和 Attention 场景开发 NVFP4 到 HiF4 的量化算法。算法可利用校准数据预先确定量化相关状态或参数，并在在线阶段对激活及Q、K、V进行动态量化。
Linear场景：
对权重进行离线HiF4量化，并结合校准信息对在线激活进行动态HiF4量化，使量化后的 Linear 输出XHIF4@WHIF4T​与原始NVFP4数据反量化后计算得到的XNVFP4@WNFFP4T​之间的MSE尽可能低。
Attention场景：
利用校准Q、K、V数据生成在线量化所需状态，并分别对在线Q、K、V进行动态HiF4量化，使量化后的Attention (QHIF4,KHIF4,TVHIF4T) 与原始NVFP4数据反量化后计算得到的Attention (QNVFP4,KNVFP4,TVNVFP4T) 之间的MSE尽可能低

选手上传算法代码包。代码包必须包含solution.py 文件，并按照接口定义实现以下6个函数：hif4_calibration_and_quantize_weight、hif4_dynamic_quantize_activation、hif4_calibration_attention、hif4_dynamic_quantize_q、hif4_dynamic_quantize_k、hif4_dynamic_quantize_v。选手可在代码包中包含其他辅助代码文件。

HiF4格式的权重量化参数
后续在线激活量化使用的 activation_state
activation_state 状态参数要求。hif4_calibration_and_quantize_weight 可根据权重及校准激活数据生成 activation_state，用于后续在线激活量化。activation_state 可保存量化算法所需的校准信息、缩放参数、固定权重信息等，但需满足以下格式要求
由权重校准阶段生成，并传递给后续在线激活量化函数，可用于保存校准参数、缩放因子、固定权重等算法状态。状态仅允许由 None、布尔值、整数、有限浮点数、字符串、CPU Tensor、list、tuple 和以字符串为 key 的 dict 组成。Tensor 支持 bool/int8/int16/int32/int64/float16/bfloat16/float32，不得包含 NaN、Inf、复数或梯度信息；状态最大嵌套深度为8，总节点数不超过4096。
Attention校准。对于每组 Attention 数据，调用选手的 hif4_calibration_attention 函数，输入若干组NVFP4格式的校准Q、K、V数据以及Head相关参数，得到后续在线量化使用的 q_state、k_state 和 v_state。上述三个参数要求参考activation。
activation_state会作为传参传入选手提供的hif4_dynamic_quantize_activation， q_state、k_state 和 v_state会传入选手提供的hif4_dynamic_quantize_q&amp;k&amp;v，选手可自定义传参内容以及传参处理方式，如无需要传参，可将相关冗余参数设为None。
Linear在线测试。对于每个测试激活数据，将校准阶段生成的 activation_state 与当前NVFP4激活数据一起传入 hif4_dynamic_quantize_activation，得到对应的HiF4激活量化参数
Attention在线测试。对于每组测试Q、K、V数据，分别调用 hif4_dynamic_quantize_q、hif4_dynamic_quantize_k 和 hif4_dynamic_quantize_v，并传入对应校准状态，得到Q、K、V的HiF4量化参数。
计算选手Linear输出。将选手生成的HiF4权重和激活参数反量化，并计算：XHIF4@WHIF4T
计算选手Attention输出。将选手生成的HiF4 Q、K、V参数反量化，并计算：Attention (QHIF4,KHIF4,TVHIF4T)
计算标准HiF4基线。使用标准HiF4量化函数对相同测试数据进行量化，并分别计算标准Linear输出和标准Attention输出。
计算每个测试用例的MSE及得分。分别计算标准HiF4输出和选手HiF4输出相对于原始NVFP4参考输出的MSE：MSESTD, MSEPLAYER, 并计算得分：
Score=(MSESTD-MSEPLAYER) / MSESTD
汇总所有测试用例得分。分别统计Linear和Attention各测试用例得分，并汇总得到最终综合评分。校准数据仅用于生成离线量化结果和在线量化所需状态，不直接参与最终得分计算。
结果合法性与异常处理。选手返回的Weight、Activation、Q、K、V量化参数必须符合HiF4格式要求；校准状态必须符合接口允许的数据格式。若单个测试用例出现超时、运行异常、缺失结果或返回非法HiF4参数，则该次提交失败。

def dequantize_nvfp4(quant_float, scale_float, blk_size=16):
    C = quant_float.shape[-1]
    assert C % blk_size == 0, f"Last dim {C} not divisible by NVFP4 block size {blk_size}"
    x = quant_float.unflatten(-1, (-1, blk_size))
    sf = scale_float.unsqueeze(-1)
    result = x * sf
    result = result.flatten(-2, -1)
    return result.to(torch.bfloat16)
